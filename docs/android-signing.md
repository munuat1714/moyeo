# Android 업로드 키 관리

모행의 Google Play 업데이트에는 최초 출시 때 사용한 동일한 업로드 키가 필요합니다.

## 필수 보관 파일

- `android/keystore/mohang-upload.jks`
- `android/keystore.properties`

두 파일은 비밀정보이며 Git에 커밋하거나 메신저로 전달하지 않습니다. 등록 담당자에게는 서명된 `.aab` 파일만 전달합니다.

## 인증서 식별 정보

- Alias: `mohang-upload`
- SHA-256: `AF:77:A5:39:4F:BB:DD:25:6E:30:DF:EB:3A:08:94:6E:FC:1A:A2:8F:C2:B5:A2:BC:AB:5C:AF:64:C9:47:7D:6E`
- 만료일: 2053-12-22

이 지문은 키를 식별하기 위한 공개 정보이며 비밀번호가 아닙니다.

## 권장 백업 방식

1. 위 두 파일을 하나의 암호화된 보관 묶음으로 만듭니다.
2. 원본 컴퓨터 외에 암호화된 USB 또는 신뢰할 수 있는 암호화 클라우드에 1부 보관합니다.
3. 보관 묶음의 암호는 파일과 다른 장소의 비밀번호 관리자에 저장합니다.
4. 팀 내 키 관리 책임자를 정하고, 분기마다 백업 파일이 열리는지 확인합니다.

현재 프로젝트 안의 파일은 로컬 원본일 뿐 백업이 아닙니다. 컴퓨터 고장이나 디스크 손상에 대비하려면 반드시 별도 저장장치에 복사해야 합니다.

## 출시 파일 생성

```powershell
npm run android:aab
```

출시할 때마다 `versionCode`를 이전 Play Console 업로드보다 크게 올려야 합니다. 키 파일이나 비밀번호가 없으면 새 출시 파일을 만들지 말고 먼저 백업본을 복구합니다.

## 분실 시 대응

Google Play 앱 서명을 사용 중이라면 Play Console에서 업로드 키 재설정을 요청할 수 있습니다. 다만 재설정에는 계정 소유자 또는 관리자 권한이 필요하므로, 정상적인 백업을 우선합니다.
