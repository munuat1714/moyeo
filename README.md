# 모두의 여행 MVP

친구들이 각자 취향을 입력하면 그룹 공통 취향을 분석해 부산 당일치기 코스 3개를 추천하고, 투표로 최종 일정을 확정하는 모바일 우선 서비스입니다. 공식 관광정보 기반의 부산 장소와 선택적 네이버 지도·지역 검색 연동을 사용합니다.

## 실행 방법

필요 환경:

- Node.js 20 이상
- npm 10 이상

```bash
npm install
npm run dev
```

터미널에 표시된 로컬 주소를 브라우저에서 열고 모바일 화면 너비로 확인합니다.

## 검증 명령

```bash
npm test
npm run build
npm run preview
```

PowerShell 실행 정책으로 `npm.ps1`이 차단되는 환경에서는 `npm.cmd`를 사용합니다.

## 네이버 API 설정

초기 서비스는 네이버 Directions를 호출하지 않아 불필요한 과금을 피합니다. 네이버 Maps의 무료 이용량은 대표 계정 등 조건이 있으므로 콘솔에서 사용량 제한과 알림을 먼저 설정하세요.

이 프로젝트의 배포 대상은 Cloudflare의 `Mirror Erigeron` 계정에 있는 `moyeo` Worker입니다. `wrangler.jsonc`의 `account_id`도 해당 계정으로 고정되어 있으므로, Variables and Secrets와 배포 설정은 반드시 이 계정에서 관리합니다.

Cloudflare Worker의 Variables and Secrets에 다음 값을 등록합니다.

```text
NAVER_MAPS_CLIENT_ID          # 네이버 클라우드 Maps Application Client ID
NAVER_MAPS_CLIENT_SECRET      # 네이버 클라우드 Maps Client Secret (Secret)
NAVER_SEARCH_CLIENT_ID        # 네이버 개발자 센터 검색 API Client ID
NAVER_SEARCH_CLIENT_SECRET    # 네이버 개발자 센터 검색 API Client Secret (Secret)
```

Web Dynamic Map Application의 허용 URL에는 다음 주소를 등록합니다.

```text
https://moyeo.moyo-ra.workers.dev
http://localhost:3000
```

키가 없으면 실제 지도 대신 동선 fallback을 표시하고, 각 장소의 네이버지도 검색 링크는 계속 사용할 수 있습니다. Secret은 GitHub와 프런트엔드 코드에 넣지 않습니다.

## 구현 기능

- 실제 장소를 출발·도착 지점으로 선택하는 부산 당일치기 여행방 생성
- 날짜, 인원, 이동수단 설정
- 만료 7일의 실제 여행방과 익명 초대 링크
- 1~6명 참여 및 취향 입력 상태의 Cloudflare D1 동기화
- 참여자별 실제 장소 취향, 음식, 분위기 복수 선택과 방문 장소 수 구간(1~2·3~4·5~6곳) 입력
- 참여자 전원 입력 전 코스 생성 잠금
- 선택 인원 기반 그룹 공통 취향 분석
- 그룹 취향이 반영된 추천 코스 3개
- 추천 코스별 지도, 상세 장소 순서와 시간 펼쳐보기(1인 예상 금액은 표시하지 않음)
- 추천 1회당 네이버 지역검색을 최대 10회로 제한하고 동시 호출을 2개로 제어
- 같은 여행방의 추천 중복 생성을 D1 단일 실행 잠금으로 차단하고 429 응답은 지수 백오프로 재시도
- 1,000개 여행방이 하루 한 번씩 추천을 생성할 때 최대 10,000회의 지역검색 호출을 사용하는 운영 기준
- 입력한 출발·도착 장소를 네이버 지역검색 좌표로 확인하고 주변 실제 장소를 우선하는 경로 기반 추천
- 출발·도착 지점이 3km 이내로 가까우면 두 지점의 중간 권역 반경 6km에서 주변 장소를 탐색
- 팀 취향 선택 빈도와 평균 방문 장소 수를 실제 검색어와 코스 장소 수에 반영
- 한식·고기·해산물·일식·중식·양식·분식·베이커리·채식 선호를 실제 음식점 검색에 반영
- 코스별 공통 60%, 차별 40% 일정 표시
- 추천 이유, 예상 가격, 이동시간, 취향 일치율 비교
- 참여자별 비공개 투표
- 투표 전 각 코스의 전체 방문 장소와 순서를 항상 표시
- 동률 시 공동 1위 후보 간 결선투표
- 투표 결과 확정 후 사용자가 `확정된 경로 보기`를 선택할 때 지도와 최종 일정 공개
- 최종 결과에서는 참여자 목록을 생략하고 초대·새 여행방·삭제 관리를 화면 하단에 배치
- 방장이 최종 일정의 장소 순서를 변경하고 네이버 실제 장소 검색으로 교체
- 날짜별 시간표와 지도형 이동 동선
- 최종 경로 제목에 실제 참여 인원 표시, 장소별 경로 카드에서는 가격 정보 제외
- 교통, 숙소, 체험 예약 연결 및 완료 상태 시뮬레이션
- 참여자 인증 토큰만 각 브라우저의 `localStorage`에 보관

## 여행방 데이터베이스

여행방·참여자 취향·투표는 Cloudflare D1의 `moyeo-db`에 저장됩니다. 이름 대신 별명만 받고 연락처는 수집하지 않습니다. 초대 URL에는 인증 토큰이 포함되지 않으며, 여행방과 관련 데이터는 생성 7일 뒤 만료되고 매일 예약 작업으로 삭제됩니다.

```bash
npx wrangler d1 migrations apply moyeo-db --local
npx wrangler d1 migrations apply moyeo-db --remote
```

새로운 마이그레이션이 생겼을 때 원격 배포 전에 위의 `--remote` 명령을 실행합니다.

## 빠른 시연

1. 홈에서 `새 여행 만들기`를 누릅니다.
2. 부산역 → 부산 조건과 방장 별명, 참여 인원을 입력해 여행방을 만듭니다.
3. 초대 링크를 다른 브라우저나 시크릿 창에서 열고 각자 별명으로 참여합니다.
4. 각 참여자가 취향을 입력하면 추천 코스 3개가 공개됩니다.
5. 각 브라우저에서 비공개 투표를 완료하고 결과를 확정합니다.
6. 최종 여행의 일정과 실제 네이버 지도 동선을 확인합니다.

우측 상단의 초기화 버튼을 누르면 처음부터 다시 시연할 수 있습니다.

## 대표 데이터

- 여행: 검색해서 선택한 부산 장소 → 부산 장소
- 기간: 선택한 날짜의 당일치기
- 인원: 민지, 서준, 유나, 현우
- 공통 취향: 맛집, 감성 카페, 사진
- 소수 취향: 역사, 액티비티

장소는 한국관광공사·부산관광포털을 참고해 2026-07-31에 검수한 부산 시드 데이터이며, 네이버 지역 검색 API가 설정되면 사용자가 요청할 때 최신 검색 결과를 확인합니다. 가격과 이동시간은 예상치이고 실제 운영시간·가격·대중교통 경로는 방문 전에 네이버지도에서 다시 확인해야 합니다. 실제 예약·결제는 진행하지 않습니다.
